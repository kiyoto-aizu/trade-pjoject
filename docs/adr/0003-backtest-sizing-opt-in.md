# ADR-0003: バックテストの本番相当サイジングはデフォルトにせずオプトインにする

- ステータス: Accepted
- 日付: 2026-09-19
- 関連: `docs/tasks/task-backtest-quantity-parity.md`, `docs/detail_design/05-backtest-design.md`（5節・10節）

## コンテキスト

バックテスト（`simulate_timeseries_backtest`）は従来、CLIの`--qty`で与えた固定数量（既定100株）にATRボラティリティ調整のみを適用しており、本番（`trading_usecase.py`）が使う「残り建玉枠で現金を按分し、`MAX_ORDER_AMOUNT_PER_TRADE`でキャップする」予算配分ロジックを反映していなかった（Issue 3）。このため、バックテストの損益・勝率・ドローダウンは資金効率まで含めた本番相当の期待値を表せていなかった。

この不一致を解消するにあたり、「本番相当の予算配分ロジックをバックテストにどう組み込むか」で以下を検討した。

## 検討した選択肢

1. **常に本番相当ロジックへ切り替える**（`qty_per_trade`固定モードを廃止し、予算配分ロジックのみにする）
   - 既存テスト29件が`qty_per_trade`固定を前提に書かれており、すべて書き換えが必要になる
   - 既存の実行スクリプト・cron等が黙って挙動を変え、過去のバックテスト結果と比較不能になる
   - `--compare-atr`/`--compare-market-regime`のようなA/Bテストで「純粋にロジックの効果だけを見たい」場合に、数量が可変になることでノイズが増える
2. **`--filtering-dir`使用時（＝実運用相当のパイプライン）は自動的に本番相当サイジングをデフォルトにする**
   - 「本番相当のデータを使うなら数量も本番相当にすべき」という理屈は一貫しているが、既存スクリプトの挙動が明示的なフラグなしに変わる点は1と同じ懸念が残る
3. **（採用）明示的なオプトインパラメータ／CLIフラグとして追加し、デフォルト動作は変えない**
   - `simulate_timeseries_backtest`に`target_positions`/`max_order_amount_per_trade`/`order_unit`を追加。いずれも未指定（`None`）なら従来の`qty_per_trade`固定のまま
   - CLIには`--production-sizing`（本番のconfig値をそのまま使う）と、個別上書き用の`--target-positions`/`--max-order-amount`を追加
   - `simulate_backtest`（レガシー・固定銘柄モード）は対象外のままとする

## 決定

選択肢3を採用する。既存の挙動・テスト・比較機能への影響をゼロにしたまま、必要なときだけ本番相当の資金効率まで含めたバックテストを選べるようにする。

## 結果（トレードオフ）

- 良い点: 既存スクリプト・cronジョブ・既存テスト29件は無変更のまま通過する（実際に確認済み）。戦略ロジックだけを見たい場合（固定数量）と、資金効率まで含めた現実的な検証（本番相当サイジング）を同じ関数で両方サポートできる
- 悪い点: **デフォルトのままでは今まで通り本番と乖離した数量で結果が出る**。`--production-sizing`を付け忘れると、資金効率の面で楽観的すぎる/悲観的すぎる数値を本番相当だと誤解するリスクが残る
   - 当面の緩和策: `docs/tasks/task-backtest-quantity-parity.md`に今週末の実行コマンド例として`--production-sizing`を明記済み
  - 将来的な見直し候補: `--filtering-dir`使用時の警告表示、または十分な運用実績が積み上がった段階で既定値を本番相当に切り替えることを再検討する
