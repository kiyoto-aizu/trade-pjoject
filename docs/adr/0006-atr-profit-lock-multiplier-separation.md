# ADR-0006: 利確用ATR倍率を損切り用と分離する

## ステータス

実装済み / 2026-09-26

## 背景・課題

ADR-0002で、ATR損切りの基準点を「エントリー価格」から「保有開始後の最高値」に
置き換えるシャンデリア・イグジット方式を導入し、同一の式・同一の倍率
(`ATR_STOP_{NORMAL,CAUTION,DANGER}_MULTIPLIER` = 1.5/1.0/0.7)で損切りと利確の
両方を兼務させていた。

その後の実データ分析(過去6ヶ月・96銘柄・エントリー条件成立1,716件、
`docs/task-backtest-quantity-parity.md`と同様の手法で日足終値ベースに簡易検証)で、
この「1本の倍率を両方に使う」設計に構造的な問題があることが判明した。

エントリー後の値動きを「保有中に一度でも0.5ATR以上の含み益を経験したか」で
2グループに分けて、倍率ごとの平均リターンを比較したところ、以下の対照的な
結果が出た。

| 倍率 | 含み益を経験した銘柄(1,257件)の平均リターン | 含み益をほぼ経験しなかった銘柄(459件)の平均リターン |
|---|---|---|
| 0.7 | +2.55% | -6.51% |
| 1.0 | +3.51% | -7.58% |
| 1.5(現行NORMAL) | +5.24% | -8.61% |
| 2.0 | +6.17% | -9.34% |
| 3.0 | +6.98% | -9.92% |

- 含み益を経験した銘柄では、倍率を上げるほど(トレーリングの余地が増えるほど)
  リターンが改善する
- 含み益をほぼ経験しなかった銘柄では、倍率を上げるほど**単調に悪化**する。
  この場合は保有中最高値がエントリー価格からほとんど動かないため、
  倍率を上げることは「トレーリングの余地を増やす」のではなく、
  **単純に損切りラインを遠ざけて含み損を深くするだけ**になる

つまり「倍率を上げる」という同じ操作が、含み益の有無によって
正反対の効果(改善 or 悪化)を生んでおり、**1本の倍率では両方に同時最適化できない**
ことが実データで裏付けられた。

## 決定

ATRベースの決済ライン計算に使う倍率を、**保有中最高値がエントリー価格から
一定以上(ATR基準)乖離しているかどうか**で2系統に分岐させる。

```
含み益 = 保有中最高値 - エントリー価格
利確モード判定 = 含み益 >= ATR × ATR_PROFIT_LOCK_TRIGGER_ATR_MULTIPLE

利確モードでない場合(含み益が乗っていない、従来の損切り局面):
    倍率 = ATR_STOP_{NORMAL,CAUTION,DANGER}_MULTIPLIER (現行と同じ、変更なし)

利確モードの場合(含み益がATR基準で一定以上乗っている):
    倍率 = ATR_PROFIT_LOCK_{NORMAL,CAUTION,DANGER}_MULTIPLIER (新設、より広め)

決済ライン = 保有中最高値 - ATR × (上記いずれかで決まった倍率)
```

- 決済ラインの計算式(基準点=保有中最高値)自体はADR-0002から変更しない。
  変更するのは「どの倍率を使うか」の1点のみ
- `ATR_PROFIT_LOCK_TRIGGER_ATR_MULTIPLE`の初期値は`0.5`とする。前述の実データ分析で
  「含み益を経験したグループ」を切り分けた閾値とそのまま一致させ、
  分析結果と実装の対応関係を明確にするため
- `ATR_PROFIT_LOCK_{NORMAL,CAUTION,DANGER}_MULTIPLIER`の初期値は`2.5/2.0/1.0`とする。
  実データ分析で「含み益を経験したグループ」のリターンが2.0〜3.0倍で頭打ちに
  近づいていたことを踏まえた暫定値。既存の`ATR_STOP_*`同様、レジームが悪化する
  ほど倍率を締める(NORMALが最も緩く、DANGERが最も締まる)という相対関係は維持する
- 含み益がない(または`ATR_PROFIT_LOCK_TRIGGER_ATR_MULTIPLE`未満)場合は、
  従来通り`ATR_STOP_*`をそのまま使う。これにより、含み益が乗っていない
  ポジションの挙動はADR-0002導入前と完全に同一のまま維持される

### 実装方針

- `domain/volatility.py`に、レベル別倍率を選ぶ`stop_loss_multiplier()`とは別に、
  含み益の有無で「損切り用」「利確用」いずれの倍率セットを使うかを判定する
  `resolve_atr_exit_multiplier()`を新設する
- `is_atr_stop_loss_triggered()`は、レベル別の3倍率を受け取って内部で選択する
  現行の責務から、**すでに選択済みの単一倍率を受け取って閾値判定するだけ**の
  責務に単純化する(倍率の選択は`resolve_atr_exit_multiplier()`側の責務にする)
- `backtest_usecase.py`(日次・分足シミュレーションの両方)と`trading_usecase.py`
  (本番トレードループ)の3箇所ある呼び出し元を、いずれも
  `resolve_atr_exit_multiplier()`経由に統一する

## 検証方法

- 実装後、`run_backtest.py`の分足バックテスト(`indicator_source=minute`)で、
  現行(`ATR_STOP_*`のみ)と新設定(`ATR_PROFIT_LOCK_*`込み)を同一期間・同一銘柄群で
  比較し、勝率・平均損益・最大ドローダウンの変化を確認する
- 日足終値ベースの簡易分析と異なり、分足データはザラ場の値動き(高値からの
  戻り)を捕捉できるため、より実態に近い検証になる

## 検討した代替案

- **倍率を一律に緩める(倍率を1本のまま引き上げる)**: 却下。前述の通り、
  含み益が乗っていない銘柄の損失を悪化させるだけで、狙った利確改善の効果を
  相殺してしまう
- **含み益額に応じて倍率を連続的に変化させる(段階分けでなく関数化)**: 却下。
  実装・検証の複雑さに対して、2段階(損切り/利確)分岐で得られる改善のほとんどを
  カバーできると判断し、まずはシンプルな2値分岐で導入する。効果が確認できれば
  将来的な拡張候補とする

## 影響・トレードオフ

- `config.py`に新規環境変数が4つ追加される(`ATR_PROFIT_LOCK_{NORMAL,CAUTION,DANGER}_MULTIPLIER`、
  `ATR_PROFIT_LOCK_TRIGGER_ATR_MULTIPLE`)
- `is_atr_stop_loss_triggered()`のシグネチャ変更に伴い、既存の呼び出し元・テストの
  更新が必要
- 実データ分析は過去6ヶ月という限られた期間(相場全体が上昇基調だった可能性がある)
  に基づく暫定値であり、下落相場を含む期間での再検証が今後必要
