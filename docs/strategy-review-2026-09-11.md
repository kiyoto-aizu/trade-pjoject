## 原因分析

銘柄選定とシグナルが以下のように逆方向だった。

| 処理 | 旧仕様 | 期待する方向 |
| --- | --- | --- |
| スクリーニング | 値上がり率と売買代金の上位銘柄を選ぶ | 上昇・注目銘柄を選ぶ |
| フィルタリング | 当日売買代金の急増率上位を選ぶ | 勢いのある銘柄を残す |
| 売買シグナル | `現在値 <= SMA5 x 0.99` かつ `RSI14 <= 30` で買い | 選定理由と同方向に買う |

結果として、上昇・出来高急増の候補に、下落・売られ過ぎが同時に起きることを要求していた。さらに上昇局面では売りシグナルが発生しても保有がないため、注文安全チェックで見送られた。

## 戦略変更

ロング専用で、上昇トレンドへの追随と失速時の決済を行う。

| 判定 | 新仕様 |
| --- | --- |
| 新規買い | `現在値 >= SMA5 x 1.01` かつ `RSI14 >= 55` |
| 決済売り | `現在値 <= SMA5 x 0.99` かつ `RSI14 <= 45` |
| 指標 | 当日を含まない確定日足から計算するSMA5とWilder方式RSI14 |

実装は`src/domain/models.py`の`TradeSignal.evaluate`に集約し、ペーパートレードとバックテストの両方が同じ判定を使う。設定は`RSI_ENTRY_THRESHOLD=55`と`RSI_EXIT_THRESHOLD=45`で環境変数から変更できる。旧環境変数の`RSI_BUY_THRESHOLD`と`RSI_SELL_THRESHOLD`は読み取り互換のため残す。

## 判断と次回評価

- 新ルールは、無取引の原因だった選定とシグナルの不整合を解消するために採用する。
- 総損益-4,000円を収益性の結論には使わない。決済済み取引が0件のため、勝率・利益因子は未評価である。
- 現在の最大ドローダウン0円も、決済済み損益を基にした集計であり、保有中ポジションの評価損益を十分に表していない。リスク評価の根拠にしない。
- 最低3か月分の候補銘柄・日足・分足を蓄積し、手数料とスリッページを含め、決済済み取引数、勝率、利益因子、最大ドローダウン、保有期間を比較する。
- 新規パラメータの再調整は、決済済み取引が十分に蓄積するまで行わない。取引回数だけを増やす目的で閾値を緩めない。
